# BCIR LLVM-First Seed

`runtime/llvm/*.ll` is the semantic source of truth for this phase.

## Field semantics
`%bcir.claim = type { i64, [4 x i32], [4 x i32], i64, [2 x i64] }`

The first `i64` is conceptually **control**:
- bits 0..7: opcode
- bits 8..15: lane
- bits 16..27: phase
- bits 28..39: epoch
- bits 40..47: flags
- bits 48..63: stride_code

Full stride encoding goes in `imm[0]` when `stride_code` is insufficient.

## Validation

The validation scripts are intended to be fail-fast when their prerequisites are installed. A recent GitHub Actions run (`CI` #310, June 4, 2026) reported the combined `LLVM seed validate` step as successful, but the workflow only ran these scripts when LLVM tools were already present. Local execution in this environment initially had no `llvm-as`, `llvm-link`, `opt`, or `llvm-dis`, and after installing the Ubuntu `llvm` package (LLVM 18.1.3) exposed a Phase 4 `bcir-as` Python syntax failure. The workflow now installs LLVM before this step and runs the scripts directly, so CI no longer silently skips expected runtime/LLVM validation.

Required tools:

- LLVM 15 or newer for opaque-pointer IR (`ptr`) and the `opt -passes=verify` pipeline.
- CI currently installs Ubuntu's `llvm` package on `ubuntu-latest`/Ubuntu 24.04, which provides LLVM 18.1.3 for `llvm-as`, `llvm-link`, `opt`, and `llvm-dis`.
- `python3` for Phase 4's BCIR assembler preflight and generated LLVM IR.

Generated-file prerequisites:

- `validate_phase4.sh` requires `tools/bcir-as/bcir-as` (the checked-in executable symlink to `tools/bcir-as/bcir-as.py`) and `examples/vector_add.bcir`.
- The script generates `build/vector_add.generated.ll`, then links it with the Phase 4 runtime modules before assembling/verifying `build/bcir_phase4_vector_add.bc`.
- Validation outputs under `build/` are disposable build artifacts and are regenerated by the scripts.
- LLVM may print `failed to infer data layout` warnings for the intentionally target-neutral `unknown-unknown-unknown` modules; the validations remain fail-fast and treat only non-zero exits or missing required symbols as failures.

Run:

```bash
runtime/llvm/validate_llvm_seed.sh
runtime/llvm/validate_phase2.sh
runtime/llvm/validate_phase3.sh
runtime/llvm/validate_phase4.sh
```

If LLVM tools are unavailable, validation is pending (do not claim success). The scripts now emit explicit preflight errors for missing LLVM commands, too-old LLVM versions, a missing Phase 4 BCIR input, or an unusable `tools/bcir-as/bcir-as`.
