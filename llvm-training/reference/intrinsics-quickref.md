# Intrinsics Quick Reference

Compact lookup for common intrinsic families. Use this table to pick the right
family, declaration shape, and verifier-sensitive constraints before jumping to
the deeper chapters.

| Intrinsic family | Signature pattern | Required attributes / `immarg` constraints | Deeper chapters |
|---|---|---|---|
| Memory copy | `llvm.memcpy.p<dst-as>.p<src-as>.<len-ty>(ptr dst, ptr src, <len-ty> len, i1 isvolatile)` | Pointer parameter attributes commonly carry `align`, `noalias`, `nonnull`, or `dereferenceable` facts; `isvolatile` is an immediate `i1` constant. Source and destination are assumed not to overlap; use `memmove` when overlap is possible. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [memory reference](intrinsics.md#memory-intrinsics), [address-space pitfalls](../08-pitfalls/11-address-space-confusion.md) |
| Memory move | `llvm.memmove.p<dst-as>.p<src-as>.<len-ty>(ptr dst, ptr src, <len-ty> len, i1 isvolatile)` | Same pointer attributes and immediate `isvolatile` rule as `memcpy`; preserves overlap semantics, so it is less freely transformable. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [memory reference](intrinsics.md#memory-intrinsics), [volatile caveat](../08-pitfalls/10-volatile-is-not-atomic.md) |
| Memory set | `llvm.memset.p<dst-as>.<len-ty>(ptr dst, i8 value, <len-ty> len, i1 isvolatile)` | `value` is an `i8`; pointer attributes normally express alignment and access facts; `isvolatile` is an immediate `i1` constant. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [memory reference](intrinsics.md#memory-intrinsics), [load/store basics](../04-memory/02-load-store.md) |
| Inline memory copy | `llvm.memcpy.inline.p<dst-as>.p<src-as>.<len-ty>(ptr dst, ptr src, <len-ty> imm-len, i1 isvolatile)` | Length is `immarg` and must be a literal constant; `isvolatile` is also immediate. Use only when the frontend requires inline-only fixed-size copying. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [memory reference](intrinsics.md#memory-intrinsics), [`immarg` pitfall](../08-pitfalls/06-immarg-violation.md) |
| Overflow-checked arithmetic | `llvm.{u,s}{add,sub,mul}.with.overflow.<T>(T lhs, T rhs) -> {T, i1}` | No `immarg` operands; declare the overload whose mangled `<T>` exactly matches the integer or vector element type. Extract field `0` for the wrapped result and field `1` for overflow. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [overflow reference](intrinsics.md#overflow-checked-arithmetic), [aggregate instructions](instruction-quickref.md#aggregate-instructions) |
| Vector integer reductions | `llvm.vector.reduce.{add,mul,and,or,xor,smin,smax,umin,umax}.<T>(<N x T> vec) -> T` | `<T>` is the vector type overload; result is the lane element type. Scalable vectors use `<vscale x N x T>` and require target/vectorizer support. | [Vectorization](../09-vectorization/README.md), [vector reference](intrinsics.md#vector-reduction-intrinsics), [special vector types](../13-advanced-ir/03-special-types-and-tokens.md) |
| Vector FP reductions | `llvm.vector.reduce.{fadd,fmul}.<T>(T start, <N x T> vec) -> T`; `llvm.vector.reduce.{fmin,fmax,fminimum,fmaximum}.<T>(<N x T> vec) -> T` | FP reassociation depends on fast-math flags or strict-FP policy; `fadd`/`fmul` include a scalar start value, while min/max families do not. | [Vectorization](../09-vectorization/README.md), [vector reference](intrinsics.md#vector-reduction-intrinsics), [fast-math flags](../13-advanced-ir/06-fast-math-flags.md) |
| Lifetime markers | `llvm.lifetime.{start,end}.p<as>(i64 imm-size, ptr addrspace(as) p)` | Size is `immarg`; use a literal byte count or `-1` for unknown size. These are optimizer hints only and do not allocate, construct, destruct, or synchronize. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [lifetime reference](intrinsics.md#lifetime-intrinsics), [`immarg` pitfall](../08-pitfalls/06-immarg-violation.md) |
| Invariant region markers | `llvm.invariant.start.p<as>(i64 imm-size, ptr addrspace(as) p) -> ptr`; `llvm.invariant.end.p<as>(ptr descriptor, i64 imm-size, ptr addrspace(as) p)` | Size is `immarg`; `end` must use the descriptor returned by the matching `start`. Only use when the memory is truly immutable for the promised region. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [lifetime reference](intrinsics.md#lifetime-intrinsics), [poison/undef/freeze](../13-advanced-ir/05-poison-undef-freeze.md) |
| Debug intrinsics / records | `llvm.dbg.{declare,value,addr}(metadata value, metadata !var, metadata !expr)` or equivalent debug records in newer textual IR | Operands use the `metadata` special type and must reference coherent `DI*` nodes; debug records/intrinsics are stripped before codegen and must not carry stale locations. | [Debug info](../06-metadata/02-debug-info.md), [debug reference](intrinsics.md#debug-info), [special metadata type](../13-advanced-ir/03-special-types-and-tokens.md) |
| Prefetch | `llvm.prefetch(ptr p, i32 rw, i32 locality, i32 cache)` | `rw`, `locality`, and `cache` are `immarg`: `rw` is `0` read or `1` write; `locality` is `0` through `3`; `cache` is `0` data or `1` instruction. It is a hint, not synchronization. | [Common intrinsics](../13-advanced-ir/01-common-intrinsics.md), [prefetch reference](intrinsics.md#prefetch-and-cache-related-intrinsics), [`immarg` pitfall](../08-pitfalls/06-immarg-violation.md) |
| Target-specific intrinsics | `llvm.<target>.<isa-or-family>.<op>[.<type-or-width>]`, for example `llvm.x86.avx2.*`, `llvm.aarch64.*`, `llvm.amdgcn.*`, `llvm.nvvm.*`, `llvm.riscv.*` | Declaration names and operands come from target `Intrinsics*.td` files; require the matching backend, subtarget features, address spaces, and ABI assumptions. Prefer target-independent IR when it states the same semantics. | [Target-specific intrinsics](../13-advanced-ir/02-target-specific-intrinsics.md), [naming reference](intrinsics.md#target-specific-intrinsic-naming-patterns), [special types/tokens](../13-advanced-ir/03-special-types-and-tokens.md) |

## Fast checklist

- Declare the exact overloaded name you call: pointer address spaces, integer
  width suffixes, vector types, and FP widths are part of the contract.
- Treat every `immarg` operand as a verifier requirement: pass a literal constant,
  not an SSA value computed earlier.
- Put semantic facts in attributes when the intrinsic expects attributes rather
  than extra operands; especially alignment and aliasing facts for memory calls.
- Use target-specific names only behind target-specific lowering paths and feature
  checks.
